# 运费大师

一个**纯前端网页应用**，用于快速计算美国、欧洲、加拿大、英国、澳大利亚的海运运费。零依赖、零构建，一个静态目录即可托管——可以直接部署到 **GitHub Pages**。价格与附加费规则都在页面里修改，自动保存在浏览器 `localStorage`。

> 也可以打包成**桌面应用**：`npm run build` 会生成一个免安装文件夹（含 `.exe` 及相关文件），整个文件夹拷走即可运行，见「[打包成桌面应用](#打包成桌面应用electron)」。
> 旧版 Electron 桌面应用的配置与现在完全互通：桌面端「导出配置」→ 这里「导入配置」即可。

## 功能

- 支持一票多箱：逐箱填写长/宽/高/实重，每箱单独计算计费重与附加费，自动汇总总运费，并给出每箱明细。
- 箱规最多 10 个，默认展示 1 个；提供「清空箱规」。
- 目的地（国家 / 地区）默认 5 个：美国（按邮编首字符分区）、欧洲（按国家）、加拿大、英国、澳大利亚；
  **目的地可以自由新增、改名、删除**（在「价格管理 → 分国家 / 地区配置」里）：
  - 点「**+ 新增国家 / 地区**」：填名称 + 选匹配方式（「直接选择国家 / 地区」同欧洲、「按邮编分区」同美国），
    新建的目的地自带 10 / 21 / 101KG+ 三档阶梯，但**不带地区行**；点「+ 新增地区」建第一行时会先弹窗问**阶梯列数**
    （默认 3 列 = 10 / 21 / 101KG+，美国是 4 列 = 10 / 21 / 71 / 101KG+，范围 1 ~ 12）；之后再加行就不再问了，表头数字可随时改
  - 列数只影响这张单价表有几档价格；调大补新列、调小从末尾删列，已有单价按位置保留（多出来的列补 0）
  - 每个国家页面顶部可以**改名称**（点本页「保存」后生效，标签栏与计算页同步更新），名称不能为空、不能重名
  - 每个国家页面顶部「**删除「XXX」**」：连同它的单价表、附加费规则、起算重量一起删除（立即生效，至少保留一个目的地）
  - 「恢复默认数据」会回到出厂的 5 个目的地，自己新增的会一起清掉
- 计费重 = max(起重, ceil(长 × 宽 × 高 ÷ 体积重系数))；**起重取报价表第一栏**（默认 10KG，改表头即改起重）。
- 附加费按目的地独立配置：**两级条件字段**（主字段 + 次级字段）+ **区间下限（≥）/上限（<）** + 金额 全部可改，可新增、可删除。
- 规则**没有单独的「启用」开关**：规则是否生效由下方「规则组组合」决定 —— 被任一组合勾选即生效，没被任何组合勾选的完全不参与计算。

  | 主字段（条件字段） | 次级字段 |
  | --- | --- |
  | 边长 | 最长边 / 次长边 / 最短边 |
  | 重量 | 计费重（材积重）/ 实重 |
  | 围长 | —（无次级，只有它自己一项） |
  | 体积 | —（无次级，只有它自己一项） |

  **一条规则 = 一个主字段 + 该主字段下的全部次级字段 + 一个金额**：

  - 选了「重量」或「边长」后，该主字段下的**次级字段会全部列出来**（如边长列出最长边 / 次长边 / 最短边），每个次级字段各有一组「下限（≥）/ 上限（<）」
  - 所有次级字段**都可以不填**：留空 = 这个次级字段不参与判断；一条都没填的规则不会命中
  - **所有次级字段是一个整体**：填过的次级字段里**任意一个满足，整条规则就命中，只按它的金额收一次**（不再是每条次级字段各收一次）
  - 跨主字段的条件（如「围长 ≥ 330 或 实重 ≥ 50」）仍是多条规则，交给「规则组组合」的行为处理

- **规则组组合独立维护**：规则列表下方有独立的「规则组组合」区。每个组合都有自己的**序号（组合 #1、#2 …）**；组合用「+ 新增组合」创建，填名字、选行为，再用**复选框**把规则（`#序号`）勾进该组合；取消勾选即移出组合。
- **互斥规则在独立区域定义**：「规则组组合」下方是「互斥规则（不与…叠加）」区，一张「组合 × 组合」的交叉表，**按组合序号打勾**即可定义哪两个组合不能同时收费（双向关系，勾一格两边都生效）。
- **组合之间默认叠加**；如果两个组合不能同时收费（如「单边」与「围长」），到下方「互斥规则」区的交叉表里**勾它们的序号**（**双向关系**：勾一格，两个方向同时生效）。命中时会在「互不冲突」的前提下收**金额总和最大**的一组组合，被跳过的组合会在结果明细里注明「未计入」。
  - 例：组合 #1 = ①330 元，#2 = ②300 元，#3 = ③300 元，交叉表勾了 #2 × #3 → 命中①②③ 收 630，命中②③ 收 300
  - 「卡派」组合永远独立累加，不受「不与…叠加」影响；「不叠加取最高」命中时，所有叠加 / 不叠加组合（含被跳过的）都不计
- **组合之间互不联动**：改 A 不会影响 B，同一条规则可以同时属于多个组合（在每个组合里各算一次，组内仍取最高）。
- 「规则组」列只是规则自己的**备注名**，与组合名**互不联动**：改组合名不会改规则组名，反之亦然；在规则表里填名字也不会自动建组合。组合的行为（叠加 / 不叠加 / 卡派 / 提醒 / 拒收）以组合区所选为准；「不叠加取最高」不在这里选，见下方独立区域。
- 价格管理按国家分子页，每个国家一页，同时包含**起算重量设置**、单价表与附加费规则。
- **未保存改动提醒**：改了但没点「保存」时，页面顶部会出现橙色提示条、对应国家标签带小圆点、保存按钮加高亮；关页面时也会兜底提示。旁边有「重新加载已保存配置」，可随时放弃改动、回到最近一次保存的状态。
  从「价格管理」切到「运费计算」时如果有未保存的改动，会**弹窗拦住**，让你选「**保存并切换**」（把所有改过的目的地 + 体积重系数一起保存）/「**丢弃修改并切换**」（回到最近一次保存的状态）/「**取消**」（留在当前页继续编辑，Esc 同效）。
- **起算重量（最低计费重）每个国家单独设置**：一箱起算多少 KG、多箱时每个箱起算多少 KG；填 0 表示不设保底。
- 可恢复默认数据（价格与规则一起恢复出厂值）。
- **配置导出 / 导入**：一键把所有配置（体积重系数 + 各目的地的阶梯、地区行、单价、附加费规则、起算重量）导出成 JSON 文件，换浏览器 / 备份 / 迁移时再导入即可；自己新增的目的地也会一起导出，导入时同样照收。
- **批量导入箱规**：直接粘贴「重量32.60kg 尺寸：69*67*59」这类文本，自动识别多行并填写到箱规表里。

## 计费规则摘要

> 下面所有数值都是**出厂默认值**，均可在「价格管理」对应国家的页面里修改，修改后即时生效。

### 通用

1. 围长 =（最短边 + 次短边）× 2 + 最长边
2. 体积重 = ceil(长 × 宽 × 高 ÷ 体积重系数)，默认系数 6000
3. **每箱单独算计费重**：计费重 = max(起算重量, 体积重)
   - 起算重量按目的地在「价格管理 → 起算重量」里设置：**只填 1 个箱**时用「一箱起算」，**填 2 个及以上箱**时每个箱各按「多箱起算（每个箱）」；填 0 表示不保底
   - 各目的地（含新增的）默认均为 10KG，即**单箱不满 10KG 也按 10KG 计**
4. **阶梯按整票（所有箱）的合计计费重取一档**，所有箱共用这个单价；合计重不满最低阶梯时按最低档算
   - 例：81 + 12 + 13 = 106KG → 全部按 101KG+ 的单价
   - 基础运费 = 各箱计费重 × 该档单价，再汇总

### 美国（叠加模式，阈值一律取「大于等于」）

| 规则组 | 条件 | 附加费 |
| --- | --- | --- |
| 实重 | 实重 ≥ 22.5KG | +120 |
| 围长 | 围长 ≥ 265 | +120 |
| 单边 | 最长边 ≥ 120CM 或次长边 ≥ 75CM（同一条规则的两个次级字段，满足其一，只收一次） | +120 |
| 超大件 | 围长 ≥ 330 或三边相乘 ≥ 283168 或实重 ≥ 50KG（满足其一） | +500 |

- 前 3 组可叠加；命中「超大件」时只收 500，前 3 组不再计入。

### 欧洲（不叠加，取金额最高）

| 条件 | 附加费 |
| --- | --- |
| 围长 ≥ 330 | +350 |
| 围长 ≥ 300 | +300 |
| 实重 ≥ 30KG | +300 |

### 加拿大（叠加模式；命中超大件只收 700）

| 规则组 | 条件 | 附加费 |
| --- | --- |
| ①实重 | 实重 ≥ 22KG | +130 |
| ②单边 | 最长边 ≥ 121CM 或次长边 ≥ 75CM（同一条规则，满足其一） | +130 |
| ③围长 | 最长边 +（宽+高）×2 ≥ 265CM | +130 |
| ④超大件 | 围长 ≥ 320CM 或 实重 ≥ 40KG（满足其一） | +700（不再叠加①②③） |
| ⑤不收货 | 实重 ≥ 68KG 或 最长边 ≥ 151CM 或 围长 ≥ 400CM（满足其一） | 不收货，计算时直接报错提示 |

### 英国（叠加模式；②与③互不叠加，①可与②/③叠加）

| 规则组 | 条件 | 附加费 |
| --- | --- |
| ①实重30-40 | 30KG ≤ 实重 < 40KG | +330 |
| ②尺寸 | 100 ≤ 长 < 150，或 70 ≤ 宽 < 100，或 60 ≤ 高 < 100（同一条规则，满足其一） | +300 |
| ③围长 | 300 ≤ 长 + 2×(宽+高) < 400 | +300 |

- ①与②同时命中叠加（630）、①与③同时命中叠加（630）、**②与③同时命中不叠加**（只收 300）。
- 配置方式：①②③ 各建一个组合（组合 #1 / #2 / #3），再到「互斥规则」区勾 #2 × #3 的交叉格（双向生效）。
- 说明：报价里的「长/宽/高」按最长边/次长边/最短边解释；③的「长+2×(宽+高)」即围长。

### 澳大利亚（叠加模式；按计费重收附加费）

| 规则组 | 条件 | 附加费 |
| --- | --- |
| 计费重≥30 | 30KG ≤ 计费重 < 35KG | +100 |
| 计费重≥35 | 35KG ≤ 计费重 < 80KG | +300 |
| 计费重≥80 | 计费重 ≥ 80KG | +300 |
| 单边120-199 | 120CM ≤ 最长边 < 200CM | +100 |
| 单边200-299 | 200CM ≤ 最长边 < 300CM | +200 |
| 木托盘提醒 | 实重 ≥ 30KG | 不收费，结果里提示「需要打木托盘」 |

### 加拿大 / 英国 / 澳大利亚的单价

- 三个目的地的**单价仍为占位值 0**，请先在「价格管理」里填写实际报价。
- 阶梯默认与欧洲一致（10KG+ / 21KG+ / 101KG+），表头可直接改。

### 附加费行为

#### 组合行为（5 种，在「规则组组合」区选）

在「附加费规则」表格下方的「规则组组合」区，创建组合 → 勾选要放进同一个组合的规则 → 为该组合选择其中一种行为（同一组合内所有规则共用同一行为，改一次整组生效）：

| 行为 | 计算方式 |
| --- | --- |
| 叠加 | **组内命中几条收几条、金额累加** |
| 不叠加 | **组内命中多条只收金额最高的一条** |
| 卡派 | 组内取最高，单独累加，**不受「不叠加取最高」和「不与…叠加」影响** |
| 提醒 | 不收钱，结果里给出提示 |
| 拒收 | 命中即不收货，计算时直接报错 |

组合之间默认相加；被「不与…叠加」连起来的组合不会同时收费 —— 命中时取**金额总和最大**的一组互不冲突的组合。

「不叠加取最高」命中时，**叠加 / 不叠加 组合全部不计**，只剩取最高的那一条 + 卡派。

#### 不叠加取最高（独立区域，优先级最高）

每个目的地在「规则组组合」下方还有一块独立的**「不叠加取最高（优先级最高）」**区，直接用复选框勾选规则：

- 命中的规则里**只收金额最高的那一条**
- 一旦命中，**所有叠加 / 不叠加组合的费用全部不计**（卡派 / 提醒 / 拒收不受影响）
- 被勾选的规则**不再按它所属的组合计算**（组合里会标注「（归取最高）」）
- 老配置里写在规则或组合上的 `max` 会自动迁移到这块区域

**组合示例**：5 条规则覆盖一个国家 — ① 叠加 100，② 叠加 200，③ 不叠加 50，④ 不叠加取最高 500，⑤ 卡派 80
- ①+② 命中 → 300
- ①+②+③ 命中 → 350
- ①+②+③+④ 命中 → 只收 ④ 500，①/②/③ 不计 → 500
- 任意组合 + ⑤ → 单独 +80

#### 互斥规则（组合之间「不与…叠加」）

「规则组组合」下方是独立的**「互斥规则（不与…叠加）」**区，一张「组合 × 组合」的交叉表，按组合序号打勾：

| | #1 | #2 | #3 |
| --- | --- | --- | --- |
| **#1** ①实重30-40 | — | | |
| **#2** ②尺寸 | | — | ✓ |
| **#3** ③围长 | | ✓ | — |

- 勾一格 = 这两个组合不能同时收费（双向，另一个方向的格子会同步打勾）
- 命中时在互不冲突的组合里收**金额总和最大**的一组，被跳过的在明细里标「未计入」
- 「卡派」组合不受互斥影响，永远独立累加；「不叠加取最高」命中时，所有叠加 / 不叠加组合都不计

**英国示例**：#1 ①330 元、#2 ②300 元、#3 ③300 元，勾了 #2 × #3
- 命中 ①+② → 630；命中 ①+③ → 630
- 命中 ②+③ → 300（只收其中一组，另一组标注「未计入」）
- 命中 ①+②+③ → 630（330 + 300）

## 使用方式

### 批量导入箱规

在「运费计算」页的箱规表格下方点「批量导入箱规」，粘贴文本后点「解析并填入」或「解析并计算」：

```
重量32.60kg 尺寸：69*67*59
重量21.50kg 尺寸：96*73*40
```

识别规则（宽松，一行一箱）：

- **重量**：优先取带单位的数字（`32.60kg` / `32.60千克` / `32.60公斤`），否则取「重量 / 实重 / weight」后面的数字
- **尺寸**：三个数字用 `x` `X` `×` `*` `·` `/` `\` 分隔（`69*67*59`、`69x67x59`、`69×67×59` 都行）
- 重量和尺寸**写在同一行或分两行都支持**（分两行时上一行的重量会配给下一行的尺寸）
- 只识别到尺寸却找不到重量时，会提示「第 N 行：识别到尺寸 …，但没找到重量」

### 导出 / 导入配置

在「价格管理」页最下方：

- **导出配置**：把当前全部配置下载成 JSON 文件（含体积重系数、各目的地（含自己新增的）的阶梯 / 地区行 / 单价 / 附加费规则 / 规则组合 / 起算重量）
- **导入配置**：选一个之前导出的 JSON，整份覆盖当前配置（会二次确认）

导出的 JSON 结构：

```json
{
  "format": "freight-master-config",
  "version": 1,
  "exportedAt": "2026-10-21T...",
  "volDivisor": 6000,
  "groups": [
    {
      "key": "us",
      "name": "美国",
      "mode": "zip",
      "minWeightSingle": 10,
      "minWeightPerBox": 10,
      "combos": [
        { "name": "实重", "mode": "add", "indexes": [0], "exclusive": [] },
        { "name": "单边", "mode": "add", "indexes": [1], "exclusive": [] }
      ],
      "maxRules": [],
      "tiers": [{ "id": 1, "min_weight": 10, "label": "10KG+" }],
      "rows": [{ "id": 1, "name": "美西（邮编8,9开头）", "matchKey": "8,9", "prices": { "1": 16.7 } }],
      "rules": [
        { "rule_group": "实重", "field": "weight", "conditions": { "weight": { "min": 22.5, "max": null } }, "amount": 120, "combine_mode": "add", "enabled": 1 },
        { "rule_group": "单边", "field": "side", "conditions": { "longest": { "min": 120, "max": null }, "second_longest": { "min": 75, "max": null } }, "amount": 120, "combine_mode": "add", "enabled": 1 }
      ]
    }
  ]
}
```

规则里 `field` 是主字段，`conditions` 里是该主字段下的次级字段条件（`min` = 下限 ≥，`max` = 上限 <，都可留空）。
组合里 `indexes` 是成员规则下标，`exclusive` 是「不与…叠加」的其他组合下标（双向关系，导入时会补成对称）。
导入时仍兼容老格式的配置（`field` + `threshold` / `threshold_max` 的旧规则在加载 / 导入时会自动转成 `conditions`），**但不会自动合并**：原来拆成两条的单边规则仍是两条，需要的话手动合到一条里。

导入时会先整份校验（格式标记、是否缺少阶梯、目的地 key 是否缺失/重复），全部通过才写入，避免写一半失败留下脏数据。
目的地不再限定为出厂的 5 个：配置里有新增的目的地（未知 key）也会照收，名称、匹配方式（`zip` / `country`）跟着文件走，缺的字段按出厂默认值补。

## 数据存在哪

**配置全部存在当前浏览器的 `localStorage`**（键名 `freight-master-config-v1`）：

- 价格与规则修改后自动保存，刷新 / 关闭浏览器不丢
- **换浏览器、换电脑、清浏览器数据都会回到出厂默认**——要迁移就先用「导出配置」备份 JSON
- 每个人的修改只影响自己的浏览器，互相不干扰（多人共用一份价格需要各自导入同一份配置 JSON）

从旧 Electron 桌面版迁移：桌面端「导出配置」→ 网页版「导入配置」即可。

## 本地开发

网页版本身零依赖、零构建，任何静态服务器都能跑：

```bash
cd freight-master
npm start        # http://localhost:5173（零依赖静态服务，也可用任何静态服务器）
```

只有**桌面应用**需要装依赖（首次执行一次即可）：

```bash
npm install      # 安装 electron / electron-builder，约 300MB，只需一次
npm run dev      # 以桌面窗口方式启动（相当于 electron .）
```

## 打包成桌面应用（Electron）

```bash
npm run build
```

产物：`dist/win-unpacked/`，里面是 **`运费大师.exe` + 相关的 dll / pak / resources 文件**。把整个 `dist/win-unpacked` 文件夹拷到任意电脑双击 `运费大师.exe` 即可运行，**免安装、不需要 Node**。

- `npm run build:installer` 额外生成 NSIS 安装包（`dist/运费大师 Setup x.y.z.exe`），需要下载 NSIS 组件
- 主进程是 `electron/main.cjs`：它会在 `127.0.0.1` 上起一个临时静态服务再加载页面 —— **不能直接用 `file://` 打开**，因为 Chromium 在 `file://`（不透明源）下会禁用 `localStorage`，而配置全存在 `localStorage` 里
- 打包配置写在 `package.json` 的 `build` 字段；`win.signAndEditExecutable` 设为 `false`，这样**不需要管理员权限或开发者模式**也能打包（代价是 exe 内部版本信息保留 Electron 默认值，窗口标题与程序名仍是「运费大师」）
- 想改 exe 的图标 / 版本信息：给 `build.win` 加 `"icon": "build/icon.ico"`，并把 `signAndEditExecutable` 改回 `true`（此时需要以管理员身份运行，或在系统里开启「开发者模式」）
- 页面里**不使用 `window.prompt` / `window.confirm` / `window.alert`**（Electron 里不支持，会直接报错）；所有询问都用页面内自绘的通用弹窗（确认 / 输入阶梯列数 / 未保存改动三选一），网页版与桌面版表现一致

## 部署到 GitHub Pages

1. 把仓库推到 GitHub（`main` 分支）：

   ```bash
   git remote add origin https://github.com/<你的用户名>/freight-master.git
   git push -u origin main
   ```

2. 仓库页面 → **Settings → Pages**：
   - Source 选 **Deploy from a branch**
   - Branch 选 `main` / `(root)`，点 Save
3. 等一两分钟，访问 `https://<你的用户名>.github.io/freight-master/` 即可。

说明：

- 仓库根目录就是网站根目录，`index.html` / `app.js` / `renderer.js` / `styles.css` 原样发布，无构建步骤
- `.nojekyll` 已放在根目录，避免 GitHub Pages 的 Jekyll 处理干扰静态文件
- 项目页面（`/<仓库名>/` 子路径）下无需任何配置，页面里所有引用都是相对路径

## 代码结构

| 文件 | 作用 |
| --- | --- |
| `index.html` | 页面结构 |
| `styles.css` | 样式 |
| `app.js` | 核心：默认数据、localStorage 持久化、运费计算、配置导入导出，并暴露 `window.freightApi` |
| `renderer.js` | 全部页面交互逻辑，只通过 `window.freightApi` 读写数据 |
| `scripts/dev-server.mjs` | 本地静态预览服务（部署用不到） |
| `electron/main.cjs` | 桌面应用主进程：起本地静态服务 + 开窗口（打包才用得到） |
| `package.json` | 脚本（`start` / `dev` / `build`）与 electron-builder 打包配置 |

## 技术栈

- 原生 HTML / CSS / JavaScript，**零依赖、零构建**
- 数据持久化：浏览器 `localStorage`
- 托管：任意静态空间（GitHub Pages 等）；桌面版由 Electron 承载同一套页面（`electron/main.cjs` + electron-builder）
